# Ulanzi Vibe Key AU05

AU05 support is opt-in and runs alongside the D200X connection loop. The AU05
works even when no D200X is attached. It is detected by USB ID `fff1:00dd`;
interface 2 provides input and interface 3 is the vendor channel. One AU05 is
supported at a time.

## USB Keepalive / Anti-Disconnect

The driver holds **both** HID descriptors open for the entire connection,
including while idle or executing an action. This is the workaround for the
firmware's approximately four-second idle disconnect/reconnect loop described
by [kubja/ulanzi-vibekey](https://github.com/kubja/ulanzi-vibekey/blob/aa827853774184b54c7d4202d06f0fc861c0898f/docs/hardware_protocol.md).
It drains input and vendor reports without writing undocumented USB commands.
Keepalive cannot be disabled independently of AU05 support.

Unplugging either endpoint closes all handles and triggers rediscovery every
second. Handles also close on shutdown or when `enabled` changes to `false`.
Binding-only config reloads keep the USB descriptors open.

## Setup

After upgrading, refresh permissions for both hidraw and input event nodes:

```sh
sudo ulanzi-niri admin-setup
```

Replug the dongle if permissions have not taken effect. Access is granted to
the active desktop session (`uaccess`) and the `input` group, not all users.
The rules retain their existing filename, `70-ulanzi-d200x.rules`, and now
cover both models.

Stop other AU05 drivers (including Typist) before starting this daemon.
By default `grab_input = true` exclusively grabs only the AU05's kernel input
event devices, preventing native Enter/Esc/scroll events from also reaching
applications. Unbound controls are suppressed too. A failed grab is treated as
a failed connection and retried, rather than silently allowing duplicate input.
`grab_input = false` retains USB keepalive but allows native input alongside
configured actions. Closing the descriptors releases the grabs.

## Configuration

Add the following **top-level** tables to `~/.config/ulanzi-niri/config.toml`.
Do not nest them within a page. Existing configurations remain disabled unless
`[au05].enabled = true`. Settings and bindings reload without restarting the
daemon; changing `grab_input` reopens the device.

```toml
[au05]
enabled = true
grab_input = true

[[au05.key]]
index = 1 # Voice
code = 0x01
on_press = { type = "exec", cmd = ["notify-send", "Voice pressed"] }
on_release = { type = "noop" }

[[au05.key]]
index = 2 # Enter
code = 0x28
on_press = { type = "media", cmd = "next" }

[[au05.key]]
index = 3 # Esc
code = 0x29
on_press = { type = "media", cmd = "prev" }

[au05.wheel]
on_rotate_cw = { type = "media", cmd = "vol-up", step = 5 }
on_rotate_ccw = { type = "media", cmd = "vol-down", step = 5 }
```

Each of the four keys (Voice, Enter, Esc, **wheel click**) can have an
`[[au05.key]]` entry with a unique `index` from 1 through 4 and independent
`on_press` / `on_release` actions. Indices are binding identifiers; `report`
and `code` select the actual HID input. Bindings are global, not page-specific,
and accept the same action types as D200X buttons. Wheel actions execute once
per detent, including reports with deltas greater than one. Repeated held-key
reports do not retrigger `on_press`.

| `report` | `code` | Decoding |
| --- | --- | --- |
| `"keyboard"` (default) | HID usage 1–255 | Report `03`, six key slots and modifiers |
| `"consumer"` | HID usage 1–65535 | Report `01`, little-endian 16-bit usage |
| `"mouse"` | Button number 1–8 | Report `02`, button bitmask |

**Wheel-click mapping is pending hardware validation.** The reference documents
Voice (`keyboard`, `0x01`), Enter (`keyboard`, `0x28`), Esc (`keyboard`, `0x29`),
and wheel rotation, but not wheel click. Capture its report before adding
`index = 4`; do not assume it is a mouse button or consumer mute. For example,
**only if your capture shows `01 e2 00` on press and `01 00 00` on release**, use:

```toml
[[au05.key]]
index = 4
report = "consumer"
code = 0xe2
on_press = { type = "media", cmd = "mute" }
```

The consumer and mouse-button layouts above are supported but also need
confirmation against the wheel-click report on real hardware. The AU05 Voice
usage `0x01` is intentionally treated as a key rather than the usual HID
ErrorRollOver error.

Keep at least one `[[page]]` in the configuration even for AU05-only use (an
empty page with `name = "main"` suffices). Display/brightness actions only
have a visible effect when a D200X is connected. Voice actions do not include
speech recognition or microphone capture.

## Hardware validation / report capture

From a source checkout, stop the running daemon and other AU05 drivers, then:

```sh
uv run python scripts/au05_monitor.py --seconds 60
```

The monitor holds both HID descriptors open without invoking configured
actions, changing firmware settings, or grabbing native input. Keep focus on
the terminal and press/release each key separately in this order:

1. Voice
2. Enter
3. Esc
4. Wheel click
5. Wheel clockwise, then counterclockwise

Raw input bytes and decoded edges are printed. Leave the device idle for the
remaining time; a successful capture should last well beyond the four-second
watchdog interval. Also check the kernel journal for USB disconnects during
this interval. The script exits on a HID read failure; `Ctrl-C` closes both
handles. Report logs contain only AU05 input, not other keyboards.

After determining wheel click, test all four actions, both wheel directions,
absence of duplicate native input, unplug/replug recovery, and enabling and
disabling AU05 through a config reload. Automated tests simulate these HID
reports and lifecycle transitions; they cannot establish physical USB stability.
